# WirePeep migration parity — published v0.1.1

[Reproducible migration size, Git range and exclusions](MIGRATION_MEASUREMENTS.md) · [Selected screenshots and exact provenance](../competition/SCREENSHOTS.md). Measurements apply only to frozen public v0.1.1 / internal rc.4.

**Current score: (15 complete + 3 partially complete × 0.5) / 18 = 91.7%.** This is a coarse functional inventory: Complete = 1, Partial = 0.5. It is not percentage of effort, source coverage or physical OS certification. Alerts, preferences and placement/tray are the three partial items. Simulation is deliberately excluded from production; tests/builds are engineering gates, not extra scored features.

Published [v0.1.1](https://github.com/samscript18/Synups/releases/tag/v0.1.1) contains unchanged application **6c812fde9a29eeb8cfd6399a2f1a75e333e81e03**, internal **0.1.1-rc.4**. The original is Bill Menees’ MIT-licensed [WirePeep at 61ae143](https://github.com/menees/WirePeep/tree/61ae14391151ca9f209223e62c98fae3df5482b8). Source links below pin those snapshots; paused development edits are not release evidence.

Evidence baseline: [exact-source native CI](https://github.com/samscript18/Synups/actions/runs/39850198899), [retained rc.4 action/test/archive reports](../evidence/verification/2026-10-22-desktop-completion.json), [all 15 public asset checks](../evidence/verification/synups-0.1.1-publication.json), [legacy semantics and intentional changes](LEGACY_SEMANTICS.md). The real-control apphost tests execute actual native applications; they do not establish physical tray, login, notification or picker delivery. [Before/after provenance](../evidence/README.md).

The row statuses total **15 Complete + 3 Partial**. Complete reflects the inventoried functional intent with disclosed safe substitutions; a physical-desktop limitation is not erased by a complete functional row. The three broader integration rows remain conservatively partial:

- **Alerts:** a notification request or sound process exit does not prove visible delivery or audible output. The Windows native attempt failed independent on-screen observation and was removed; accessible in-app feedback remains.
- **Preferences:** controls and persisted intent exist, but an actual later OS login and removal at that login have not been observed.
- **Placement/tray:** handlers, geometry and restore behavior exist, but physical tray menus and real multi-display restoration are not accepted by programmatic control invocation.

## Why this migration was technically difficult

| Original problem / source | Implemented solution | What was verified |
|---|---|---|
| WPF `App` and `MainWindow` own lifetime, command routing, row composition, logging and exit disposal; the executable mutex silently ignores duplicates. | Avalonia desktop lifetime, explicit composition, workspace-scoped activation and awaited closing replace those coupled boundaries. The existing instance restores rather than silently swallowing a launch. | Actual rc.4 apphosts start minimized, restore via a second executable, cancel exit confirmation and exit after saving; no physical tray claim. |
| `StateManager.Update` uses synchronous parallel ping and the window timer owns overlap prevention; disposing a timer cannot await an in-flight callback. | `MonitoringService` owns async group tasks, a lifecycle gate, bounded concurrency and cancellation/draining; a late OS call remains owned in Stopping. | Engine overlap/cancellation/shutdown tests and actual extracted stop/restart stages. This is more than replacing XAML. |
| `PeerGroupState`/`LocationState` couple rotating selection, per-target eligibility, first-success exit and failure-grace timestamps. Reordering calls can alter incidents. | `GroupMonitor` preserves sorted rotation, early success and the 20 ms predicate, freezes a session configuration and uses monotonic intervals. | Five linked-original characterization tests plus migrated-engine boundary cases; the [semantics audit](LEGACY_SEMANTICS.md) separates preserved intent from corrections. |
| A legacy Ping exception is Unavailable and can clear failure; the last unsuccessful peer can determine group state. Wall-clock gaps can look like continuous downtime. | Typed probe outcomes, order-independent indeterminate state and explicit observation gaps; only measured success recovers a confirmed incident. | Error/mixed-peer/grace/recovery tests; source-qualified [isolated real incident](../competition/INCIDENT_DEMO.md), not invented production values. |
| `LogRow` is session-memory state and `Logger` is a close-time text stream. There is no durable replay protocol. | One serialized SQLite owner commits events/incidents/session state atomically, retains pending writes on error and marks interrupted observations without recovery. | History/capacity/busy/full/corruption tests, genuine previous-version data copies, process-kill and read-only failure/repair stages. rc.3 incident-demo evidence stays labelled rc.3. |
| Registry startup, WinForms tray/balloons, WPF taskbar/media and Menees window persistence cannot run unconditionally on macOS/Linux. | Platform-contained login, native alert/sound and tray adapters; geometry clamping and conservative fallbacks preserve a usable window. | Native runtime/control checks on three OSs and safe unsupported/failure paths; delivery, audibility, later login and physical menus remain explicitly partial. |
| Menees settings serialization is external to the original repository; inventing its file format would not prove compatibility. | Generate a real 5.1.2 `.stgx` fixture from untouched upstream on Windows, parse a bounded profile subset read-only, preview, confirm and back up Synups before replacement. | All three rc.4 native import/backup/reload reports and corrupt/unsupported-schema tests. Source settings and OS registrations remain unchanged. |
| Self-contained managed builds still require correct native SQLite/graphics/text assets, executable modes and macOS bundle handling. | Per-RID portable packaging retains runtimes, MIT/notices, exact source manifests and byte hashes; tests extract and execute the delivered apphost. | Windows/macOS/Linux six-stage archive execution, file/CPU/native-library checks and anonymous public asset verification. Signing/notarization and every desktop environment remain separate. |

## Preserved, improved and new are different claims

**Original/preserved:** literal-IP peer groups, timing, sorted rotating alternatives, first success, failure grace, incident/comments and logging/export intent. **Changed/improved:** cancellable bounded execution, monotonic duration, honest uncertainty, durable SQLite, backup/restart/retention and explicit discovery/import. These changes improve the existing workflow without adding score rows. **Still partial:** the three delivery/login/physical-integration rows above. Simulation remains intentionally absent from production.

**Additional alpha work:** the separate `0.2.0-alpha.1` Diagnostics workspace at `3c4462a71cbb90032603cd3eaf4366c2561474d7` adds protocol tests, incident-linked diagnostic sessions, baselines/comparisons and redacted PDF/JSON/Markdown evidence. It is not included in the v0.1.1 downloads and earns **no legacy parity points**. Its [31-feature matrix](https://github.com/samscript18/Synups/blob/feat/network-diagnostics/docs/diagnostics/FEATURE_MATRIX.md) and [hardening report](https://github.com/samscript18/Synups/blob/feat/network-diagnostics/docs/diagnostics/HARDENING_REPORT.md) use independent scopes, test counts, assets and limitations.
